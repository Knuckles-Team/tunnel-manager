# CONN-TUNNEL-MANAGER-INVENTORY requirements

Every requirement this specification owns, with the proof that closes it. Delivery state and
public evidence for each ID are recorded in [`status.json`](status.json); this file defines what
each ID means. The design is in [`spec.md`](spec.md) and [`plan.md`](plan.md), the test contract
in [`test-spec.md`](test-spec.md), and the work order in [`tasks.md`](tasks.md).

| ID | Requirement | Verification |
|---|---|---|
| `CONN-TUNNEL-MANAGER-INVENTORY-R001` | **One canonical host inventory path across surfaces.** tunnel-manager resolves the shared host inventory from exactly one path, `$XDG_CONFIG_HOME/scion-sdk/inventory.yml` (using the XDG platform default when unset), with no working-directory, packaged-resource, legacy `.yaml`, or per-service fallback, and every CLI, library, MCP, and container surface reads that same file. Caller chain: every surface (CLI, library, MCP tools, container) calls `default_inventory_path` (tunnel_manager/tunnel_manager.py:388) to find the inventory file. Shape: `default_inventory_path` in `tunnel_manager/tunnel_manager.py` returns the single path `$XDG_CONFIG_HOME/scion-sdk/inventory.yml` and drops the `agent-connectors` directory and the legacy `.yaml` fallback; the container mounts that file read-only. Proving test: `tests/test_inventory_path.py::test_single_canonical_inventory_path`. Proving test: `tests/test_inventory_path.py::test_single_canonical_inventory_path`. | A fixture with only the canonical file present confirms every automatic reader resolves it, while a container-mount test confirms the deployed container reads the identical file read-only. |
| `CONN-TUNNEL-MANAGER-INVENTORY-R002` | **Fleet name.** `pyproject.toml` declares `tunnel-manager-mcp` as the single `scion_sdk.connector` entry point. The content pack, the manifest `connector`, the fingerprints and the ingest binding all carry `tunnel-manager-mcp`. Caller chain: `tunnel-manager` in `pyproject.toml` runs `tunnel_manager.tunnel_manager:main`, which builds the server from the `scion_sdk.connector` entry point `tunnel_manager:connector` (`tunnel_manager/__init__.py:129`); `connector_name("tunnel_manager")` in the SDK resolves the same entry point name for the content pack, the manifest and the ingest binding. Shape: `pyproject.toml` entry point `tunnel-manager-mcp`, the `connector_name` helper of the SDK and the `ConnectorContent`/`IngestBinding` calls under `tunnel_manager/`; reuses the SDK name resolution and adds no second constant. Proving test: `tests/test_fleet_name.py::test_connector_name_is_the_fleet_name`. | Every connector name in the package is `tunnel-manager-mcp`. |
| `CONN-TUNNEL-MANAGER-INVENTORY-R003` | **SSH runs without a local username.** Every SSH connection uses the inventory entry's `user` explicitly and never depends on the local process username, so a container uid with no passwd entry and no `USER`/`LOGNAME` still connects. Tool failures are logged with their cause. The published image creates the runtime uid as a real user with a home directory. Caller chain: an MCP tool of `tunnel_manager/mcp_server.py` builds a `Tunnel` from the inventory entry (`tunnel_manager/mcp_server.py:397`), whose `user` is passed to paramiko explicitly. Shape: `Tunnel` in `tunnel_manager/tunnel_manager.py` resolves the username from the inventory entry and never calls `getpass.getuser` first; tool failures log their cause. Proving test: `tests/test_no_local_username.py::test_tunnel_uses_explicit_user_without_local_username`. | With `getpass.getuser` raising `OSError`, a `Tunnel` built from an inventory entry resolves its username, and a failing tool call logs the underlying exception. |
| `CONN-TUNNEL-MANAGER-INVENTORY-R004` | **A failed inventory write leaves no trace.** When the inventory projection is read-only or a save fails, `add_host` and `remove_host` raise and restore the in-memory host table, so a later `get_host` or `list_hosts` never reports a host that was not persisted. Caller chain: the `tunnel_manager_add_host` and `tunnel_manager_remove_host` MCP tools call `HostManager.add_host` and `HostManager.remove_host`. Shape: both methods in `tunnel_manager/tunnel_manager.py` snapshot the previous entry, save, and roll back on any save error. Proving test: `tests/test_inventory_rollback.py::test_failed_add_host_does_not_leave_a_ghost`. | With `save_inventory` raising, `add_host` raises and the alias is absent; `remove_host` raises and the alias is still present. |
| `CONN-TUNNEL-MANAGER-INVENTORY-R005` | **Structured jump host replaces free-form proxy arguments.** An inventory entry may name `jump_host`, the alias of another inventory entry. The connector must reach the target through that entry, verify the host key of each hop against its own known-hosts record, and authenticate each hop with its own entry. A chain must hold at most 3 hops and must refuse a cycle. The proxy-command allowlist in `proxy_security.py` must keep refusing `-o ProxyJump`, `-J` and nested `ProxyCommand` text, so jump routing has exactly one structured path. An alias the caller is not entitled to must refuse as a typed permission error. Caller chain: tm_remote tools and `tm_inventory` -> `HostManager.get_host` -> remote_execution.py and async_tunnel.py connect paths (proxy handling at remote_execution.py:589 and async_tunnel.py:78). Shape: one `jump_host` field in the inventory schema and one hop-resolver beside `proxy_command_argv`; no shell string reaches the SSH client. | `tests/test_jump_host.py::test_jump_host_chain_verifies_each_hop_and_refuses_free_form_arguments` builds a two-hop chain over fake transports, asserts per-hop host-key checks and refusal of a cycle, a fourth hop, `-J` and `-o ProxyJump`. |
| `CONN-TUNNEL-MANAGER-INVENTORY-R006` | **First contact pins the host key against an operator fingerprint.** The connector must keep `RejectPolicy` for unknown hosts and must keep refusing a key scan. An inventory entry may carry `host_key_fingerprint`, a SHA-256 fingerprint the operator obtained out of band. The tool `tm_pin_host_key` must connect, read the presented key, compare its fingerprint with the entry, and only on an exact match append the key to the entry's known-hosts file. A mismatch, a missing fingerprint or a host that already holds a different key must refuse without writing. The tool must be marked destructive for confirmation and must never log a key. Caller chain: MCP tool tm_pin_host_key -> `HostManager.get_host` -> tunnel_manager.py known-hosts helpers (`validated_known_hosts_path`, L611 area). Shape: one tool and one comparison helper; the trust decision stays with the operator-supplied fingerprint. | `tests/test_pin_host_key.py::test_pin_writes_only_on_a_matching_fingerprint` asserts the known-hosts file changes only on a match and that each refusal leaves its bytes unchanged. |
| `CONN-TUNNEL-MANAGER-INVENTORY-R007` | **Key rotation verifies the new key and updates the inventory.** `rotate_ssh_key` and `rotate_ssh_key_on_inventory` must open a fresh connection with the new identity through the host's own route, including its proxy command or jump host, before they remove the old key from `authorized_keys`. If that login fails, the connector must keep the old key and report the host as unrotated. After success the connector must update the entry's identity file through the atomic write rules of `CONN-TUNNEL-MANAGER-INVENTORY-R004`, so no manual client update remains. A bulk rotation must report one outcome per host and must not stop at the first failure. Caller chain: MCP tools tm_remote_rotate_key and tm_inventory_rotate_key -> tunnel_manager.py::Tunnel.rotate_ssh_key (L1576) and `rotate_ssh_key_on_inventory` (L1825). Shape: add the verify step and the inventory update after `_apply_rotated_authorized_keys`; keep the old key until the verify step passes. | `tests/test_rotate_key_verified.py::test_old_key_is_kept_until_the_new_key_logs_in_and_inventory_is_updated` covers a failed verify, a passing verify with a jump host, the inventory update and the per-host bulk report. |

The pack never imports the core ontology. Caller chain: the MCP ingest of hosts calls `ingest_hosts`, which calls `observes_machine`. Shape: one ontology edit, two mapping edits and one loop edit. Depends: SCION-CENTRALIZED-CAPABILITIES-R057.1. The owning change adds each new file named here. | `tests/test_machine_rollup.py::test_host_rolls_up_to_machine_and_ingest_emits_observes_links` and `::test_a_refused_key_skips_the_link_and_keeps_the_record`. |
| `CONN-TUNNEL-MANAGER-INVENTORY-R008.2` | **Hardware facts tool.** Subsystem: host inventory. Add the action `get_hardware` to `_TM_SYSTEM_ACTIONS` in `tunnel_manager/mcp_server.py` (the table that `_tm_system_dispatch` at line 4741 reads). Register the granular tool `tm_system_get_hardware` in `register_system_tools` beside `tm_system_get_info`. Parameters: `remote_host: str`, `credential_ref: str`, `username: str = ""`. The credential reference resolves through the SDK credential resolver, as `password_ref` does. Add `SystemIntelligence.get_hardware_inventory()` in `tunnel_manager/system_intelligence.py`. It runs only these fixed read-only commands: reads of `/sys/class/dmi/id/product_uuid`, `product_serial`, `sys_vendor` and `product_name`; `lscpu -J`; `lsblk -J -b -o NAME,MODEL,SERIAL,SIZE,ROTA,TRAN,TYPE`; reads of `/sys/class/net/<name>/address`, `speed` and `operstate`; reads of `/proc/net/bonding/<bond>`; `lspci -mm -nn`; `/proc/meminfo`; `dmidecode -t memory` when allowed; and `nvidia-smi --query-gpu=name,memory.total,serial,pci.bus_id --format=csv,noheader,nounits` when present. No command takes caller input. The result has the schema `inventory-probe-system/v1` of the arbora contract. A host that cannot connect returns `{schema, reachable: false}`. The tool carries `readOnlyHint` true and never returns a credential. Caller chain: MCP tool `tm_system_get_hardware` calls `call_routed(_tm_system_routed, "get_hardware", ...)`, then `_tm_system_dispatch`, then `_tm_system_get_hardware`, then `get_hardware_inventory`. Shape: one new action handler beside `_tm_system_get_info` and one new method beside `get_system_info`. Depends: none. The owning change adds each new file named here. | `tests/test_system_hardware.py::test_hardware_payload_matches_the_probe_schema`, `::test_unreachable_host_returns_reachable_false`, `::test_only_fixed_read_only_commands_run`, `::test_no_credential_appears_in_the_payload`. |
